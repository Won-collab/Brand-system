Logo usage rules
Do

Use the wordmark on approved background colours only: white, Forest-900, Lime-100, and Sand-200.

Do

Use the app icon mark in place of the wordmark at small sizes (below 80px width) or in constrained UI contexts such as favicons and app tiles.

Do

Maintain the minimum clearspace (cap-height x) on all four sides. Never let content encroach into this zone.

Don't

Don't recolour the wordmark. Only use black on light backgrounds, or white on dark backgrounds.

Don't

Don't stretch, skew, rotate, or apply shadows, gradients, or outlines to the wordmark.

Don't

Don't use the wordmark on busy photographic backgrounds without a solid colour underlay. Always ensure sufficient contrast.

Additional variants needed for a complete fleet design system

Sparklines (inline micro-trends)

Stat cards currently show only a % delta. Sparklines give the directional shape at a glance within the card footprint. Use Chart-1 for positive trend, Chart-3 for negative.

Heatmap / Calendar matrix

Critical for maintenance scheduling and activity density. Use the sequential ramp on a calendar grid. Each cell = a day, colour intensity = cost or event count.

Empty / zero-data state

All chart types need a defined empty state: illustration placeholder + body copy. Use Sand-200 for the "no data" illustration tone, never the primary chart colours.

Error / failed-to-load state

Network error variant for every chart card. Use Service-Due amber token for the alert icon. Include a retry affordance.

Status token spec (complete)

The current draft has 4 chart colours but no named semantic status tokens. Define Active, Review, Service Due, and Inactive as named tokens in the design file variables.

Dark-mode surface variants

The graphic component page shows light + dark card surfaces but the graph test page only has a white background. Define chart grid line, axis label, and legend colours for Forest-900 background.
